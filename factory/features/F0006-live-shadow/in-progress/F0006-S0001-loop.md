# The loop

## Description

The core, the adapters and the router exist one by one. This story ties them together in one pure C module, the loop, that the firmware glue and the shadow sketch will both call:

- The loop takes an input as it arrives (a room payload, the outdoor temperature, the produced heat, the valve, the defrost flag, the PV power), runs it through its adapter, and hands any reading to the core at once.
- Called often with the current instant, the loop advances the core every `integration_interval_s` (10 s). Every `tick_interval_s` (60 s) it turns the room average into an indoor reading, lets the core decide, steps the router, and returns a record of the decision.
- A formatter writes that record as one line of text, with fixed decimals, without `printf` of floats.
- A small clock module widens a 32-bit millisecond counter, which wraps every 49.7 days, to one that does not (`docs/control/firmware-design.md` §5).

Cooling is masked off by default: the loop allows heating and no demand only.

## Interface

New files: `HeishaMon/src/control/loop/ctl_loop.h`, `ctl_loop.c`, `ctl_clock.h`, `ctl_clock.c`, `ctl_format.h`, `ctl_format.c`. Test files: `tests/control/test_loop.c`, `tests/control/test_clock.c`, `tests/control/test_format.c`. The loop uses the core, `ctl_rooms`, `ctl_pump`, `ctl_solar` and `ctl_router` as they are, and changes none of them.

```c
/* ctl_clock.h */
typedef struct { bool started; uint32_t last_ms; uint64_t high; } ctl_clock;
void ctl_clock_init(ctl_clock *clock);
uint64_t ctl_clock_widen(ctl_clock *clock, uint32_t now_ms);

/* ctl_format.h */
bool ctl_format_fixed(double value, int decimals, char *text, size_t size);

/* ctl_loop.h */
typedef enum { CTL_INPUT_ROOM, CTL_INPUT_OUTDOOR, CTL_INPUT_HEAT, CTL_INPUT_VALVE,
               CTL_INPUT_DEFROST, CTL_INPUT_PV } ctl_input;
typedef enum { CTL_INPUT_TAKEN, CTL_INPUT_NO_READING, CTL_INPUT_REFUSED, CTL_INPUT_BAD } ctl_input_status;

typedef struct {
    ctl_config core;
    ctl_rooms_config rooms;
    ctl_router_config router;
    uint8_t allowed;      /* CTL_DEMAND_BIT of each allowed demand; default HEATING and NONE */
    bool assume_landed;   /* default false; true: every command counts as landed at the next step */
} ctl_loop_config;

typedef struct {
    ctl_state state;
    ctl_rooms rooms;
    ctl_pump pump;
    ctl_router router;
    bool confirmed_known;
    int confirmed_state;
    double next_advance;
    double next_evaluate;
} ctl_loop;

typedef struct {
    double t;
    ctl_decision decision;
    ctl_rooms_average rooms;
    ctl_commands commands;
    ctl_router_status router_status;
} ctl_loop_record;

void ctl_loop_config_defaults(ctl_loop_config *config, size_t room_count);
bool ctl_loop_config_valid(const ctl_loop_config *config);
void ctl_loop_init(ctl_loop *loop, const ctl_loop_config *config, double now);
ctl_input_status ctl_loop_input(ctl_loop *loop, const ctl_loop_config *config, ctl_input input,
                                size_t room, const char *payload, size_t length, double now);
void ctl_loop_confirm(ctl_loop *loop, bool known, int state);
bool ctl_loop_tick(ctl_loop *loop, const ctl_loop_config *config, double now, ctl_loop_record *record);
bool ctl_loop_format_record(const ctl_loop_record *record, char *text, size_t size);
```

The clock:

- The first call returns `now_ms` and starts the clock.
- Each later call with `now_ms` below the previous one adds 2^32 to `high`.
- Every call returns `high + now_ms`.

The fixed format:

- `ctl_format_fixed` writes `value` with exactly `decimals` digits after the point, from 0 to 3. With 0 there is no point.
- It rounds half away from zero.
- It writes `-` before a negative result, and no sign before a result that rounds to zero (`-0.004` with 2 decimals is `0.00`).
- NaN is written `nan`, and the infinities `inf` and `-inf`.
- It returns false, and writes nothing, when `decimals` is outside 0 to 3, when the magnitude is at least 1e12, or when `size` cannot hold the text with its terminating zero.

The configuration:

- `ctl_loop_config_defaults` sets the core's defaults, `ctl_rooms_config_defaults` for `room_count` rooms, the router's defaults, `allowed` to the bits of `HEATING` and `NONE`, and `assume_landed` to false.
- `ctl_loop_config_valid` is true when:
  - `ctl_config_validate` returns 0;
  - the rooms' and the router's configurations are valid;
  - `allowed` has no bit above the three demand bits.

`ctl_loop_init`:

- It initialises the state, the rooms, the pump and the router.
- It calls `ctl_set_allowed` with `allowed` at `now`.
- It sets the confirmation to unknown.
- It sets `next_advance` to `now + integration_interval_s` and `next_evaluate` to `now + tick_interval_s`.

`ctl_loop_input`:

- `CTL_INPUT_BAD` for an `input` that is no member of the enum. For a room, also for a `room` not below the rooms' `count`. For anything, also for a `now` that is not finite.
- A room goes to `ctl_rooms_offer`. `CTL_ROOM_ACCEPTED` gives `TAKEN`, and every other room status gives `REFUSED`; no reading reaches the core until the next decision tick.
- The other inputs go to their adapter: `ctl_pump_outdoor`, `ctl_pump_heat`, `ctl_pump_valve`, `ctl_pump_defrost`, and `ctl_solar` with `solar_gain_factor` of the core's configuration.
  - A reading goes to `ctl_observe` at once and gives `TAKEN`.
  - No reading after an accepted value (a valve that did not change) gives `NO_READING`.
  - A refused value gives `REFUSED`.

`ctl_loop_confirm` stores what the glue knows about the thermostat state the pump reports.

`ctl_loop_tick`, for a finite `now`; otherwise it returns false and changes nothing:

1. When `now >= next_advance`, it calls `ctl_advance` to `now` and sets `next_advance` to `now + integration_interval_s`.
2. When `now >= next_evaluate`, it decides:
   - it asks `ctl_rooms_average_at` at `now`;
   - with an average, it calls `ctl_observe` with `T_INDOOR`, the average and `now`;
   - it calls `ctl_evaluate` at `now`;
   - it calls `ctl_router_step` with the decision's demand. With `assume_landed`, the confirmation passed is known and equal to the router's `sent_state` before the step; otherwise it is what `ctl_loop_confirm` stored;
   - it sets `next_evaluate` to `now + tick_interval_s`;
   - it fills the record with `now`, the decision, the average, the commands and the router's status after the step, and returns true.
3. Otherwise it returns false.

The record's text, from `ctl_loop_format_record`: the fields below, separated by single spaces. It returns false when `size` is too small.

- `t=` the instant, 1 decimal;
- `demand=`, `reason=`, `phase=`: the names of the core's enums;
- `E=` the energy, 1 decimal;
- `pnet=` the net balance, 0 decimals, or `-` without inputs;
- `indoor=`, `outdoor=`: the inputs, 2 decimals, or `-` without inputs;
- `produced=`, `solar=`: the inputs, 0 decimals, or `-` without inputs;
- `rooms=` the fresh count, `:`, the fresh weight with 1 decimal, `/`, the total weight with 1 decimal;
- `router=IDLE`, `WAITING` or `FAULT`;
- `cmd=` the commands as `name:value` joined by `,`, or `-` when there are none.

`CTL_LOOP_TEXT_MAX`, defined in `ctl_loop.h` as 256, is enough for every record.

9. The router, as rows of one table test:

11. `make check` stays green, and `make device` compiles with the new folder.
